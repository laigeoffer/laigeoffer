### Q：项目负责什么，你做的这个模块做了什么

A1：我在项目中主要负责 project 模块的后端开发，该模块是 PmHub 的核心，可以自定义项目和任务，以及分配任务，还可以在任务中添加评论，任务完成后可以通过审批流进行任务流转，实现项目-任务之间的完美闭环。

![PmHub 项目管理页面](https://cdn.tobebetterjavaer.com/stutymore/real-interview-20240809175114.png)

在任务审批设置时，为了保证审批状态一致性，我使用了基于 Redis 的分布式锁，通过自定义注解+ AOP 完成了加锁和解锁的控制。

在添加任务时，需要添加成员、更新审批设置、更新日志等一系列操作，我通过 Seata 添加分布式事务，通过 @GlobalTransactional 注解保证添加任务时的事务一致性。

在新建任务后，需要指派人员，并通知到对应的人员，我使用了 RocketMQ 来进行消息推送，实现了异步解耦的同时极大的提高了系统的稳定性。

A2：在 PmHub 项目中，我主要负责的是 pmhub-auth 认证中心模块。这个模块的核心职责是管理和验证用户身份，确保只有经过认证的用户才能访问系统的各种资源和功能。

![PmHub 权限管理](https://cdn.tobebetterjavaer.com/stutymore/real-interview-20240809175052.png)

我使用了 Spring Security 和 JWT 来实现这些功能。具体实现上，我首先配置了 Spring Security，定义了各种认证和授权规则，包括为不同的 URL 路径设置不同的访问控制策略。

在身份验证过程中，我使用了 JSON Web Token (JWT) 来管理用户会话。每当用户成功登录时，系统会生成一个 JWT 令牌，并将其返回给客户端。这个令牌包含了用户的身份信息和权限信息，并经过签名以防止篡改。客户端在后续的请求中会携带这个令牌，服务器则通过验证令牌的签名来确认用户的身份和权限。

在权限管理方面，我采用了基于角色的访问控制（RBAC）模型。每个用户可以拥有一个或多个角色，每个角色定义了一组权限。通过这种方式，可以灵活地管理用户的访问权限。例如，管理员角色拥有对所有资源的访问权限，而普通用户角色仅能访问其个人数据和有限的功能模块。
